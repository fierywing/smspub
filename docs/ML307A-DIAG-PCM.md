# ML307A 诊断口语音 PCM 逆向结论

实测日期：2026-10-23；接收工具与复核更新至 2026-10-24。对象：`card3`（电信 460-11），固件 `ML307A-DSLN-MTSH1S00`。方法：CATStudio V3.1.0.85 逆向资料（见 [音频链路分析报告](CATStudio_音频链路分析报告.pdf)）+ CATCore.dll 反汇编 + 诊断口实机探测。读取过日志并发送过管理握手与应用命令探测，未刷写固件；不能把早期未知命令探测描述为完全被动。

## 核心结论

**2026-10-24 最新恢复结果**：card3 的诊断口（当前 ttyUSB22）已通过 AT 口发送 `AT+LOG=11,0` 恢复日志输出，关闭再打开后仍有持续记录。这条命令选择 USB 日志路由并写入配置，未验证整机重启后的持久性。来源、实测统计与操作步骤见 [恢复记录](ML307A-DIAG-RECOVERY.md)。以下早期“card3 无响应”的内容为恢复前历史；恢复日志不等于已实现通话上行。

**ML307A-DSLN 在诊断日志可用时，无需改固件即可从诊断口实时捕获通话 PCM。**AT 手册标注 PCM 流录放不支持、AT 实测返回 ERROR，与诊断接收并不矛盾：语音走的是**诊断日志通道**，不是 AT 或独立 USB 音频接口。最初未连接诊断客户端的 usbmon 测试无音频流，不能推导为 USB 永远不能导出语音。CATStudio 报告描述了类似 Voice Logging 编译开关，但当前固件的具体开关和运行时开启条件尚不明确。

**实测通话（51 秒，电信 VoLTE）从诊断口完整恢复出 16kHz/16bit 双向语音**：拼接 WAV 后能量包络呈现清晰的说话/停顿交替，与通话过程一致；数据流在通话结束后停止。**录音已经人耳确认可懂（2026-10-23，通话双方语音清晰）。**

## 诊断口与记录格式（逆向所得）

| 项 | 结论 |
|---|---|
| 物理通道 | USB interface 1.4 `Mobile Diag Interface`（VID 2ECC / PID 3012；option 驱动绑成 ttyUSB）。中移驱动包 `mdiagusb.inf` 确认该接口装 `icatusb_DDI`（ASR iCat 诊断驱动），与 CATStudio 通信模型一致 |
| 固件身份 | 上报版本串 `CRANE_CAT1_CP_SDK_1.011.078_02X_CPONLY__A01606_PS_LTE_Only_GIT_daily_20221201`、`CRANEL_CAT1_M1_L1_SDK_1.011.076`（CRANE=ASR1606；LTE Only 印证电信 VoLTE 无 CS 回落） |
| 触发方式 | 日志路由选择 USB（card3 实测恢复命令 AT+LOG=11,0）后，诊断口发送已知 ACATReady/GetCPDBVer 握手，持续外送 CP 日志（空闲约 20KB/s）；不需要发送任意或未知命令 |
| 上行记录 | `[len:u32 小端=记录总长含本字段][pad:u16=0][seq:u16 递增][type:u16][sub:u16][ts:u32][payload]`。实测 2596+398650 条记录链式解析 100% 对齐，seq 跨读取连续 |
| ts 时基 | 32.768kHz 音频时钟（PCM 帧间增量 656 tick ≈ 20.020ms） |

## 通话 PCM 流（本次目标）

- **记录标识**：`(type,sub) = (0x0019,0x0a6c)` 与 `(0x0027,0x1d10)` 两条流**内容逐条相同**（固件把同一路语音记到两个日志点），取其一即可。
- **节奏**：每 20ms 一条（一帧）；仅在通话建立后出现，空闲与挂断后均无。
- **payload 结构**（固定 3200B）：16-bit 小端样本，按 int16 样本计 `[0:320)` 与 `[320:640)` 为两个 20ms 声道（16kHz），对应字节区间 `[0:640)`、`[640:1280)`，其余字节为 0。拼接任一声道即得连续音频：`帧数 × 20ms = 通话时长`（实测 2798 帧 = 56.0s ✓）。
- **带宽**：原始日志流通话中约 350–500KB/s（PCM 本体仅 64KB/s）；诊断口吞吐满足实时要求。
- 声道与上下行（发/收）的对应关系尚未区分（两声道均有语音能量；无 mic 的板卡上行仍记录到能量，可能为处理链中间点）。

## 下行命令格式（2026-10-24 实机命令表更正）

**官方参考实现已找到**：CATStudio 包内 `Exec/DiagSaver_Linux.zip` 是 Marvell/ASR 出品的 Linux 诊断客户端 **C 源码**（DiagSaver v3.0），给出了完整握手：

```c
ACATReady  = 10 00 00 00 | 00 04 FF FF | 00*8   // 客户端注册
GetAPDBVer = 10 00 00 00 | 80 00 FF FF | 00*8   // 取 AP 侧 DB 版本
GetCPDBVer = 10 00 00 00 | 00 00 FF FF | 00*8   // 取 CP 侧 DB 版本
```

**实测 ML307A-DSLN 应答**：握手后返回 CP DB 版本 **`0x4AED`**（记录 len=0x1B、type=0xFFFF/sub=0、payload ASCII `"0x00004aed"`）。AP 侧无应答——与固件版本串 `CPONLY` 一致（无 AP）。**该 DB 版本号是向中移 OneMO FAE 索取配套诊断 DB/工具的关键凭据。**

以下偏移从长度字段之后的 body 起算。已用带符号 SDK 与当前量产固件的只读命令表交叉核对：

| 字段 | 含义 |
|---|---|
| `[len:u32]` | 总长，包含 4 字节长度字段 |
| `byte0` | SAP：本次原生 CP 应用函数命令使用 1；管理握手使用 0 |
| `byte1` | service：应用函数使用 0；管理握手的 4/0 分别为 Ready/DB 查询 |
| `u16@2` | module，应用函数可填 0；管理握手为 0xFFFF |
| `u32@4` | **原生函数 command ID**，即整帧偏移 8，绝非 Audio/DSP 目标子系统 |
| `u32@8` | 保留 0 |
| body 偏移 12 之后 | 函数参数，即整帧偏移 16 之后 |

应用帧构造为 `struct.pack('<IBBHII', 16 + len(params), 1, 0, 0, command_id, 0) + params`。

**撤回早期“target=0x0F 是唯一响应目标、target=3 Audio 无应答”的结论**：所谓 target 实际是函数编号。先前填入 15 调用的是 `getIfDataStat`，填入 3 调用的是统计函数；不能据此判定音频接口不存在，也不能把这些响应认作音频未知 opcode。早期 PXA 表盲扫没有正确定位本固件的音频函数，已停止使用。

当前固件 CP DB 为 0x4AED，命令范围为 0–908。已验证只读函数 350/351（远端/近端静音查询）与 372（语音测试控制查询），并成功通过 606/607 启停远端 AMR 播放。**2026-10-24 07:53 的真实电话中，对端用户已确认清楚听到经 USB 上传的测试音。**详见 [USB 通话上行记录](ML307A-DIAG-TX.md)。

**重要更正（2026-10-23 深夜复核）**：先前“0x80 探测致诊断服务关闭”的归因未成立。card3 完整断电重启后，诊断口对 ACATReady/旧触发字节/裸 USB 批量端点均无响应，而当时其他 4 块未重启模组正常。**已知观察是 card3 重启后日志不可用；不能据单卡观察确定所有量产固件默认关闭，也未证明此前日志为何开启。**开启机制已列入 [FAE 问询](FAE-问询-ML307A-DSLN-诊断DB与IMS.md) 问题 4。2026-10-24 复核另 3 块空闲模组仍正常，card3 仍无响应；第 5 块未确认空闲，未采集。后续工具只发送 ACATReady/GetCPDBVer，不再探测 AP/未知 DSP 命令或重启模组。

**注入（放音）路线现状，2026-10-24 更新**：已实现“主机生成 AMR → USB 诊断文件写入 → 模组远端播放 → 对端电话听到”，无需模拟音频接线、外接声卡或刷机。后续连续内存上行与网页麦克风已实现，验证范围见 [连续上行记录](ML307A-DIAG-STREAM.md)。匹配诊断 DB 与厂家流式接口资料仍有价值，但已不是文件上行验证的前置阻点。详见 [已验证命令、文件命名空间与验收边界](ML307A-DIAG-TX.md)。

其他已验证的"出声"途径（2026-10-23 实测）：`AT+VTS` DTMF 固件接受（对端未听到，疑似运营商不渲染 telephone-event）；文件上传（`MFCFG` HEX 编码 + `MFOPEN/MFWRITE/MFCLOSE` 分块，实测 32KB/s）+ 通话中 `MAUDPLFILE` 播放成功（状态机全程播放），但 PCM 取证证明**只进本机输出总线、不混入上行**——无法用于注入。

## 工具

```bash
# 列出诊断接口及稳定 by-path 路径；不能把 AT 接口填进来
python3 tools/diagpcm.py --list

# 只统计日志与 DB 响应，不输出或保存语音；无记录退出码 3，错误退出码 2
python3 tools/diagpcm.py <诊断口by-path> --probe --duration 3

# 通话中增量写入 WAV，Ctrl-C 或到时关闭；不覆盖已有文件
python3 tools/diagpcm.py <诊断口by-path> /tmp/call.wav --duration 60

# 纯 PCM 实时管道（双声道时需同时指定 --channel stereo 和播放器 -ac 2）
python3 tools/diagpcm.py <诊断口by-path> --pcm - | ffplay -f s16le -ar 16000 -ac 1 -

# 独立浏览器试听，默认仅监听 127.0.0.1:8081，不自动打开诊断口
python3 tools/diaglisten.py <诊断口by-path>
# 远程主机可用 ssh -L 8081:127.0.0.1:8081 asuna 后访问 http://127.0.0.1:8081
```

浏览器点“开始收听”后才连接，停止或关闭页面后释放诊断口；同时只允许一个收听者。网页不录音、不采集麦克风、不调用拨号 API；拨号/接听仍用 smspub 的电话窗口。浏览器排队上限约 300ms，积压时丢帧追赶，实际端到端延迟需实话测量。

修复了旧脚本合并两条镜像 PCM 流导致重复播放/时长翻倍的问题，默认锁定首条有效流；`--stream 19/27` 可固定。支持 `--channel 0/1/stereo`，双声道输出已交错，不能据此命名为上行/下行。WAV 逐帧写入，不再把整通电话样本堆在内存；解析支持跨 read 分片、限制记录长度、统计失步跳过字节和序号跳变。对普通日志需相邻记录的序号证据才恢复边界，已知 PCM/DB 响应则按完整特征识别；协议没有 magic，重同步仍是启发式处理。

工具校验 2ecc:3012 与接口号 04，拒绝 AT 口，使用排他锁并在结束时恢复 termios。诊断口与 smspub 的 AT 队列是不同 USB 接口，不需要重启短信服务；不要同时运行多个诊断客户端。音频与原始抓包只保存到仓库外。

## 意义与边界

- 电脑侧获得通话音频的“收”方向已有可懂录音；实时 PCM 输出、WAV 录音和独立浏览器试听已实现，生产页面现已集成 USB 收听和拨号通话界面。新浏览器工具的实话可听性和端到端延迟仍需单独验收。
- “发”方向已通过真实电话验证 USB 上传文件的远端播放；对端已确认听到测试音。连续内存上行与网页麦克风已实现，验证范围见 [连续上行记录](ML307A-DIAG-STREAM.md)。
- 该通路是诊断/校准用途的日志机制，非正式产品接口：带宽波动、日志开关状态、固件版本差异都可能影响稳定性，正式使用需按固件版本回归验证。
- 原始取证（含语音内容的 WAV/抓包）仅在本机 /tmp 或用户缓存目录留样，未入库。

## 当前网页集成（2026-10-24）

当前 Go 服务通过 `internal/voice` 读取已确认的同模组 interface 04，复用本文记录格式与镜像去重、双声道交错规则，向首页电话窗口发送 16 kHz PCM。接口及页面使用方式见 README「网页电话」与 [后端契约](BACKEND.md)。仅收听模式发送 Ready/CP DB 管理握手；新增麦克风模式在已核对固件上使用受限音频 RAM 写入。两种模式均不写日志路由配置，不打开 RNDIS 接口。音频连接断开、慢客户端超时或网页停止后恢复串口属性并释放排他锁。跨站请求、错误声道、离线卡片在打开硬件前拒绝。

界面集成测试使用模拟呼叫和合成 PCM 验证拨号、计时、多卡来电接听、最小化后继续收听、挂断、音频占用错误与重连。既有真实电话证据仍适用，但新页面未重新完成真实双向听音验收，麦克风实时上行后续已实现，参见 [连续上行记录](ML307A-DIAG-STREAM.md)。

运行验证：Go 全量测试、音频/HTTP/串口相关 race 检查及 Linux arm64 构建通过；原有 Python 工具 60 项测试通过。Firefox 实测拨号、计时、多卡接听、挂断、音频错误后恢复及 390px 页面布局，合成 PCM 在原生 AudioContext 中调度且左右样本一致。正式服务已读取 card3 的真实空闲诊断记录，第二个收听者返回 409，停止后可重连。自动 AT 探测另排除了 ML307A 的 interface 00/01/04，避免网络/诊断口被当成 AT 接口探测。临时空卡预览服务仍会探测未知串口（auto_cards 只控制是否加卡），现已关闭；后续浏览器测试应使用不暴露真实串口的隔离环境。
